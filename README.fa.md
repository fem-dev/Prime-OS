# پرایم‌اواس (Prime-OS)

> یک پروژهٔ آزمایشی و مستقل است: هیچ نرم‌افزار یا درایور اختصاصی بازتوزیع نمی‌شود، هیچ‌چیز تضمین‌شده
> نیست، و انتخاب درایو اشتباه یا استفادهٔ نادرست از ابزار می‌تواند داده‌ها را از بین ببرد.

**پرایم‌اواس** یک پروژهٔ جامعه‌محور برای ساخت یک سیستم‌عامل گیمینگ بر پایهٔ **Arch Linux** و
میزکار Wayland **Hyprland** است. مرحلهٔ فعلی یک **ISO زندهٔ قابل‌بوت و آزمایشی** است؛ نه نصب‌کنندهٔ
کامل و نه سیستم‌عامل آمادهٔ استفادهٔ روزمره.

> [!IMPORTANT]
> هیچ بخشی از این مخزن سیستم‌عامل شما را جایگزین نمی‌کند. برنامهٔ راه‌انداز فقط یک ایمیج زنده دانلود
> می‌کند و فایل ترجیحات را ذخیره می‌کند؛ پارتیشن‌بندی، نوشتن روی فلش و نصب انجام نمی‌دهد. اول ایمیج
> را در ماشین مجازی امتحان کنید و برای تست روی کامپیوتر واقعی از فلش خالی استفاده کنید.

## شروع سریع

**لازم نیست لینوکس، Docker یا هیچ مرحلهٔ ساخت داشته باشید.** ویزارد خودش `os.iso` را از آخرین
Release مخزن گیت‌هاب دانلود می‌کند .

### ویندوز

```powershell
irm https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.ps1 | iex
```

### لینوکس و مک

```bash
curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.sh | bash
```

پیش‌نیازها: **Python 3 همراه Tk**، **Git**، اینترنت، و فضای خالی کافی برای ایمیج. بستهٔ Pillow
به‌صورت خودکار در یک محیط مجازی خصوصی نصب می‌شود.

ویزارد این کارها را می‌کند:

1. آخرین Release گیت‌هاب را برای فایل `os.iso` بررسی می‌کند؛
2. آن را در پوشهٔ برنامه دانلود می‌کند و هم‌زمان تصویر را پر می‌کند؛
3. حجم فایل و در صورت وجود، SHA-256 منتشرشده را بررسی می‌کند؛
4. پروفایل سخت‌افزاری شما را ذخیره می‌کند.

اگر هنوز هیچ Release منتشر نشده باشد، صریح همین را می‌گوید و فقط پروفایل را ذخیره می‌کند — هرگز
ادای نصب درنمی‌آورد.

| | ویندوز | لینوکس / مک |
| --- | --- | --- |
| فایل‌های برنامه | `%LOCALAPPDATA%\Prime-OS` | `~/.local/share/prime-os` |
| ترجیحات | `%APPDATA%\Prime-OS\setup.json` | `~/.config/prime-os/setup.json` |

## اجرای ایمیج زنده

فایل `os.iso` را با هر ابزار نوشتن ایمیج روی یک فلش خالی بنویسید، یا مستقیم در یک ماشین مجازی
UEFI بوت کنید.

```bash
# QEMU، دیسک فقط-خواندنی؛ چیزی روی سیستم اصلی تغییر نمی‌کند
qemu-system-x86_64 -m 4G -smp 2 -cpu max -enable-kvm \
  -drive file=os.iso,media=cdrom,readonly=on -boot d
```

در ویندوز، اسکریپت `./run-windows.sh` فایل `out/os.iso` را از Git Bash در QEMU بوت می‌کند
(نصب QEMU لازم است).

### کلیدهای میان‌بر

| کلیدها | کار | کلیدها | کار |
| --- | --- | --- | --- |
| `Super + Enter` | ترمینال (Kitty) | `Super + Q` | بستن پنجره |
| `Super + D` | فهرست برنامه‌ها (Wofi) | `Super + F` | تمام‌صفحه |
| `Super + B` | Firefox | `Super + V` | شناور کردن پنجره |
| `Super + G` | Steam | `Super + P` / `Super + J` | شبه‌کاشی / تقسیم |
| `Super + N` | تنظیمات شبکه | `Super + M` | خروج از Hyprland |
| `Super + 1…9` | تغییر میزکار | `Super + Shift + 1…9` | انتقال پنجره به میزکار |

## این نسخهٔ آزمایشی چه دارد

- محیط زندهٔ Arch Linux ساخته‌شده با پروفایل رسمی `archiso` (releng).
- Hyprland، Waybar، Wofi، Kitty، Dunst، NetworkManager و PipeWire/WirePlumber.
- Steam، Lutris، Firefox و درایورهای معمول Mesa/Vulkan.
- یک جلسهٔ گرافیکی حداقلی با کاربر عادی و بدون دسترسی ریشه به نام `prime`.
- ویزارد فروهر برای ویندوز، لینوکس و مک.

**هنوز پیاده‌سازی نشده:** نصب‌کننده روی دیسک، پشتیبانی Secure Boot، فرایند به‌روزرسانی و بازیابی،
تنظیم خودکار سخت‌افزار و پروفایل‌های آزمایش‌شده برای هر GPU. یک ISO نمی‌تواند همهٔ درایورهای
اختصاصی را داشته باشد؛ پشتیبانی NVIDIA به مدل کارت بستگی دارد.

## امنیت و یکپارچگی

- ماژول تصویری `you.py` روی HTTPS گرفته می‌شود، با SHA-256 پین‌شده بررسی می‌شود و فقط **پارس**
  می‌شود؛ هرگز اجرا نمی‌شود.
- لوگو قبل از رمزگشایی از نظر حجم و تعداد پیکسل محدود و با هش پین‌شده بررسی می‌شود.
- آدرس دانلود Release باید HTTPS و متعلق به مسیر `releases/download` همین مخزن باشد.
- دانلود در فایل `.part` انجام می‌شود و تنها پس از تطابق حجم — و در صورت وجود، checksum منتشرشده —
  جای‌گذاری می‌شود.
- اسکریپت‌ها SHA-256 هر فایلی را که نصب می‌کنند بررسی می‌کنند.
- هش‌های منتشرشده در `install.sh`، `install.ps1` و `loader.py` پین شده‌اند و باید هم‌زمان با تغییر
  آن فایل‌ها به‌روزرسانی شوند.

خودتان ایمیج را بررسی کنید:

```bash
sha256sum os.iso          # با یادداشت‌های Release یا فایل checksum مقایسه کنید
```

اگر هش مطابقت نداشت، ایمیج را بوت نکنید و گزارش دهید.

## ساخت ISO (فقط برای توسعه‌دهندگان)

ساخت اختیاری است و فقط وقتی لازم است که بخواهید خود ایمیج را تغییر دهید. Docker و چند گیگابایت
فضای خالی می‌خواهد.

```bash
git clone https://github.com/fem-dev/Prime-OS.git
cd Prime-OS
docker run --rm --privileged \
  -e PRIME_OS_BUILD_CONTAINER=1 \
  -v "$PWD:/work" -w /work archlinux:latest \
  bash -lc 'pacman -Syu --noconfirm archiso && bash ./build.sh'
```

اسکریپت `build.sh` بیرون از کانتینر Archِ نشان‌دار اجرا نمی‌شود، پروفایل رسمی releng را در
`.build/profile` کپی می‌کند، مخزن `multilib` را فقط در همان پروفایل موقت برای Steam فعال می‌کند،
`profile/packages.x86_64` را ادغام می‌کند و خروجی را در `out/os.iso` می‌نویسد.

ویندوز به‌طور مستقیم نمی‌تواند ISO آرچ بسازد — از WSL2 با توزیع Arch یا از `build.ps1` همراه
Docker Desktop استفاده کنید.

### ساخت در CI (GitHub Actions — بدون ساخت روی سیستم خودتان)

1. از تب **Actions → Build and publish ISO → Run workflow** اجرا کنید.
2. تگ Release را وارد کنید (پیش‌فرض `os-preview`)؛ اگر نبود ساخته می‌شود.
3. کار در یک کانتینر Docker با دسترسی privileged ساخته می‌شود، **فقط یک نوار پیشرفت** نشان می‌دهد و
   در پایان `os.iso` و `os.iso.sha256` را روی همان Release می‌گذارد. لاگ کامل به‌عنوان artifact می‌ماند.

پوش کردن یک تگ `v*` هم همین کار را می‌کند. لازم نیست چیزی روی سیستم خودتان بسازید؛ برای تست
تعاملی هم می‌توانید در Codespace همان دستور Docker را اجرا کنید و wrapper پیشرفت آنجا هم کار می‌کند.

## ساختار مخزن

| مسیر | کاربرد |
| --- | --- |
| `loader.py` | ویزارد راه‌اندازی: یافتن Release، دانلود ISO، پیشرفت تصویری، پروفایل |
| `install.sh` / `install.ps1` | نصب یک‌دستوری برای لینوکس/مک و ویندوز |
| `you.py` | رندر برداری فروهر (به‌عنوان داده ارسال می‌شود؛ پارس، بدون اجرا) |
| `faravahar.png` | لوگوی ویزارد و جلسهٔ زنده |
| `profile/packages.x86_64` | بسته‌های اضافه که به پروفایل archiso اضافه می‌شوند |
| `profile/airootfs/` | فایل‌های داخل ایمیج زنده (Hyprland، Waybar، ورود خودکار، اسکریپت راه‌اندازی) |
| `build.sh` / `build.ps1` | ساخت تکرارپذیر ISO در Docker |
| `run-windows.sh` | بوت ISO ساخته‌شده در QEMU از Git Bash |
| `requirements.txt` | وابستگی پایتون (`Pillow`) |
| `NOTICE.md` | این پروژه چیست و چه نیست: لایسنس‌ها، علامت‌های تجاری، ایمنی، وضعیت |
| `.github/` | workflow ساخت ISO و انتشار خودکار در Releases |

جلسهٔ زنده یک‌بار و روی `tty1` توسط drop-in ورود خودکار `getty` به‌همراه `/etc/skel/.bash_profile`
شروع می‌شود؛ `prime-os-live-setup` کاربر بدون‌ریشهٔ `prime` را می‌سازد و کانفیگ مرجع
`/etc/prime-os/hyprland.conf` را نصب می‌کند.

## وضعیت پروژه

این نقطهٔ شروع است، نه ادعای یک سیستم‌عامل کامل. قدم‌های بعدی: آزمایش ایمیج منتشرشده روی
سخت‌افزار واقعی، رفع مشکلات راه‌اندازی و بسته‌ها، طراحی نصب‌کننده، و سپس پروفایل‌های گیمینگ
آزمایش‌شده و فرایند به‌روزرسانی و بازیابی. گزارش تست سخت‌افزار و مشارکت پذیرفته می‌شود.

## مشارکت

- صداقت ایمیج را حفظ کنید: ادعای «بدون لگ» و عدد عملکردی بدون اندازه‌گیری ممنوع.
- اول در ماشین مجازی تست کنید و هرگز از کاربر نخواهید فلشی را که اطلاعات دارد پاک کند.
- اگر `loader.py`، `you.py` یا `faravahar.png` را تغییر دادید، هش‌های پین‌شده در نصب‌کننده‌ها را در
  همان کامیت به‌روز کنید؛ نصب‌کننده‌ها عمداً «fail closed» رفتار می‌کنند.
- مدل GPU، نسخهٔ درایور و نتیجهٔ تست خود را گزارش دهید.
