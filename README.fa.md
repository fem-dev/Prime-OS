# Prime-OS

**یک نصب‌کنندهٔ کوچک و بوت‌شدنی که می‌پرسد چه می‌خواهی، و فقط همان را نصب می‌کند.**

Prime-OS یک سیستم بر پایهٔ Arch Linux و Hyprland است که یک قاعده دارد: فایلی که
دانلود می‌کنی **نصب‌کننده** است، نه یک دسکتاپ آماده. حجمش چند صد مگابایت است،
هیچ برنامه‌ای داخلش نیست، و وقتی بالا می‌آید می‌پرسد کدام بخش‌ها را می‌خواهی.
بقیه در همان لحظهٔ نصب، تک‌تک و فقط همان بخش‌هایی که انتخاب کردی، از مخازن Arch
گرفته می‌شود.

هیچ فایل عکسی در پروژه نیست: نه کاغذدیواری، نه لوگوی تصویری. نشست با رنگ‌های
ساده و تعریف‌شده در [`branding/palette.json`](branding/palette.json) خودش را
می‌کشد.

---

## چطور کار می‌کند

۱. **ایمیج را بوت کن.** کنسول اول به‌صورت خودکار با root وارد می‌شود و برنامهٔ
نصب را اجرا می‌کند؛ بقیهٔ کنسول‌ها یک شل معمولی می‌مانند.
۲. **سخت‌افزار و شبکه را بررسی می‌کند** و اگر به مخازن Arch نرسد، صریح می‌گوید.
۳. **دیسک را انتخاب می‌کنی.** همیشه باید کلمهٔ `ERASE` را تایپ کنی و روی دیسکی
که پارتیشن mount‌شده دارد دست نمی‌زند.
۴. **بخش‌ها را تیک می‌زنی**: دسکتاپ، درایور گرافیک، فونت‌ها، برنامه‌ها. هر بخش
یک فایل جداست؛ چیزی که تیک نزنی نصب نمی‌شود و قبل از تأیید، حجم دانلود را
می‌بینی.
۵. **نصب می‌کند**: `pacstrap` فقط پکیج‌های بخش‌های انتخاب‌شده را می‌نویسد، بعد
overlay نشست Prime-OS را روی سیستم جدید می‌گذارد، بوت‌لودر نصب می‌شود و حساب
کاربر ساخته می‌شود.
۶. **ری‌استارت.** روی ماشین نصب‌شده همان چیزی هست که انتخاب کردی، و نه بیشتر.

چیزی که ایمیج **عمداً** ندارد: دسکتاپ، برنامه، درایور، یا کپی کامل سیستم. کل
ایده همین است — همان چند بخشی که خودت انتخاب می‌کنی، بهتر از یک ایمیج بزرگ که
حدس می‌زند.

## نصب

سه راه ورود وجود دارد و این سه با هم قابل تعویض نیستند؛ هر کدام مال یک سیستم
عامل است. ردیفی را انتخاب کن که ماشینت را توصیف می‌کند.

| چه می‌خواهی | ماشینت | کجا |
| --- | --- | --- |
| نصب Prime-OS روی همین کامپیوتری که پشتش نشسته‌ای | **لینوکس**، از یک نشست زندهٔ Arch | [لینوکس: یک خط](#لینوکس-یک-خط) |
| نصب Prime-OS از روی فلش | **ویندوز، مک یا لینوکس** | [هر سیستم‌عاملی: ایمیج نصب](#هر-سیستم‌عاملی-ایمیج-نصب) |
| دانلود ایمیج در یک پنجرهٔ دسکتاپ، بعد خودت استفاده کنی | **ویندوز، مک یا لینوکس** | [هر سیستم‌عاملی: دانلودر دسکتاپ](#هر-سیستم‌عاملی-دانلودر-دسکتاپ-اختیاری) |

### لینوکس: یک خط

**فقط لینوکس.** این دستور مخزن را می‌گیرد، ابزارهایی که ویزارد لازم دارد را
نصب می‌کند و ویزارد را اجرا می‌کند. به یک نشست زندهٔ Arch نیاز دارد —
[ایمیج رسمی Arch](https://archlinux.org/download/) یا یک ایمیج نصب Prime-OS که
از فلش بوت شده — و روی سیستم نصب‌شدهٔ عادی اجرا نمی‌شود، پس دیسک ماشین کاری‌ات
به‌اشتباه پاک نمی‌شود.

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/setup.sh)"
```

نشست زنده خودش با root وارد می‌شود، پس این خط به `sudo` نیاز ندارد؛ اگر با حساب
دیگری اجرا می‌کنی، `sudo` را اولِ کل خط بگذار. شکل دستور را عوض نکن و آن را به
صورت `curl … | bash` اجرا نکن: ویزارد صفحه‌های تمام‌صفحه می‌کشد و کلیدها را از
کنسول می‌خواند، و لوله (pipe) کنسول را با متن اسکریپت عوض می‌کند؛ در آن حالت
ویزارد کیبوردی ندارد، همان را می‌گوید و می‌ایستد.

بعد از آن همه‌چیز یک پرسش است: دیسک (باید `ERASE` را تایپ کنی)، بخش‌ها، حساب
کاربری. اگر همین دستور را روی ایمیج نصب Prime-OS اجرا کنی، از نسخه‌ای که روی خود
ایمیج هست استفاده می‌کند و چیزی دانلود نمی‌کند.

`PRIME_OS_REF` تعیین می‌کند از چه چیزی نصب شود — هر برنچ، تگ یا کامیت. پیش‌فرض
`main` است:

```bash
PRIME_OS_REF=main bash -c "$(curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/setup.sh)"
```

اگر با حساب معمولی و `sudo` اجرا می‌کنی، متغیر باید به محیط `sudo` هم برسد:
`PRIME_OS_REF=main sudo -E bash -c "$(curl …)"`.

وای‌فای خودش وصل نمی‌شود: در کنسول زنده `nmtui` را اجرا کن، وصل شو، و بعد دستور
را دوباره بزن. این راه روی ویندوز و مک وجود ندارد — آن ماشین‌ها نه نشست زندهٔ Arch
دارند نه `pacman`؛ از ایمیج نصب پایین استفاده کن.

### هر سیستم‌عاملی: ایمیج نصب

این راه مال **ویندوز، مک و لینوکس** است. یک فایل دانلود می‌کنی، بررسی‌اش می‌کنی،
روی فلش می‌نویسی و ماشین را از همان فلش بوت می‌کنی. ویزاردِ روی فلش همان ویزاردی
است که دستور یک‌خطی بالا اجرا می‌کند.

**۱. دانلود.** `os.iso` و `os.iso.sha256` را از
[آخرین نسخه](https://github.com/fem-dev/Prime-OS/releases) بگیر.

**۲. بررسی دانلود** — برای هر سیستم‌عامل یک دستور، و نتیجه را با محتوای
`os.iso.sha256` مقایسه کن.

لینوکس:

```bash
sha256sum -c os.iso.sha256
```

مک:

```bash
shasum -a 256 -c os.iso.sha256
```

ویندوز (PowerShell):

```powershell
(Get-FileHash .\os.iso -Algorithm SHA256).Hash
Get-Content .\os.iso.sha256
```

**۳. نوشتن روی فلش.** این کار فلش را پاک می‌کند، نه کامپیوتر را.

لینوکس — `/dev/sdX` همان فلش است، با `lsblk` دو بار چکش کن:

```bash
sudo dd if=os.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

مک — `diskutil list` فلش را نشان می‌دهد، مثلاً `disk4`؛ روی گرهٔ `rdisk` بنویس:

```bash
diskutil unmountDisk /dev/disk4
sudo dd if=os.iso of=/dev/rdisk4 bs=4m
```

روی **ویندوز** از [Rufus](https://rufus.ie) یا
[balenaEtcher](https://etcher.balancer.io) استفاده کن و `os.iso` را انتخاب کن.
اگر Rufus دربارهٔ حالت ISOHybrid پرسید، **Write in DD image mode** را بزن.

**۴. بوتش کن.** منوی بوت فریم‌ور (معمولاً `F12`، `F11` یا `Esc` هنگام روشن‌شدن)
را باز کن، فلش را انتخاب کن؛ برنامهٔ نصب روی کنسول اول شروع می‌شود.

### هر سیستم‌عاملی: دانلودر دسکتاپ (اختیاری)

یک پنجرهٔ کوچک که `os.iso` را دانلود می‌کند، SHA-256اش را بررسی می‌کند و در
پوشهٔ مناسبی نگه می‌دارد. هیچ‌وقت روی فلش نمی‌نویسد، پارتیشن‌بندی نمی‌کند و سیستم
عامل نصب نمی‌کند: بعد از آن خودت باید فلش را بنویسی. اگر فایل را داری، از این
بخش رد شو.

لینوکس — به `curl`، `python3`، `venv` و Tk نیاز دارد
(`sudo apt install curl python3 python3-venv python3-tk` روی دبیان/اوبونتو،
`sudo pacman -S curl python tk` روی آرچ):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.sh)
```

مک — فایلش `install-mac.sh` است، نه `install.sh`: آن یکی به `sha256sum` نیاز دارد
که روی مک وجود ندارد. به Python 3 از python.org نیاز دارد (Tk همراه خودش است):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install-mac.sh)
```

ویندوز — PowerShell 5.1 یا جدیدتر، بدون دسترسی administrator. به Python 3 از
python.org نیاز دارد با گزینه‌های «Add python.exe to PATH» و «tcl/tk and IDLE»:

```powershell
irm https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.ps1 | iex
```

اگر گامی از دانلودر شکست بخورد، دلیلش را می‌گوید و لاگ می‌گذارد: روی ویندوز در
`%TEMP%\prime-os-install.log`، روی لینوکس و مک روی همان صفحه. اگر پنجره اصلاً باز
نشد، نسخه را دستی دانلود کن؛ آن راه فقط به مرورگر نیاز دارد.

## ساختن ایمیج

بیلد به `archiso` و root نیاز دارد، پس در کانتینر اجرا می‌شود — **روی یک ماشین
لینوکسی با داکر** (نه مستقیم روی ویندوز یا مک):

```bash
docker run --rm -it --privileged -e PRIME_OS_BUILD_CONTAINER=1 \
  -v "$PWD:/work" -w /work archlinux:latest
# داخل کانتینر:
pacman -Syu --noconfirm archiso
bash build.sh
```

`out/os.iso` همان نصب‌کننده است. GitHub Actions با هر push روی `main` آن را
می‌سازد و منتشر می‌کند ([`.github/workflows/build-iso.yml`](.github/workflows/build-iso.yml))؛
پس برای گرفتن ایمیج لازم نیست خودت بیلد کنی.

## روی سیستم نصب‌شده

| مسیر | چیست |
| --- | --- |
| `~/.config/hypr/hyprland.conf` | نشست: کلیدها، حاشیه‌ها، رنگ‌ها. |
| `~/.config/waybar/` | نوار. |
| `/etc/prime-os/install.conf` | این ماشین با چه چیزی نصب شده: بخش‌ها، دیسک، فایل‌سیستم، تاریخ. |
| `/usr/share/prime-os/keys.txt` | فهرست کلیدها، روی دیسک، تا `Super+/` بدون شبکه هم کار کند. |

`Super+Enter` ترمینال، `Super+D` لانچر، `Super+/` همان فهرست کلیدها. ورود root
روی سیستم نصب‌شده قفل است؛ حسابی که در نصب ساخته می‌شود در گروه `wheel` است و
از `sudo` استفاده می‌کند.

## وضعیت، صادقانه

- ایمیج یک **نصب‌کننده** است. هنوز نصب روی سخت‌افزار واقعی با کاربران زیاد
  آزمایش نشده؛ اولین نصب را آزمایشی بدان و پشتیبان داشته باش.
- سیستم نصب‌شده **ابزار به‌روزرسانی ندارد**: Arch خالص است، پس راه به‌روزرسانی
  `pacman -Syu` است.
- Secure Boot تنظیم نشده.
- به‌جز بیلد، چیزی خودکار تست نمی‌شود: ویزارد تست ندارد و CI فقط بررسی می‌کند
  ایمیج ساخته شده و اندازه‌اش درست است.
- فقط همین فایل فارسی و فایل انگلیسی مرجع‌اند. بقیهٔ ترجمه‌ها (`README.*.md`)
  نسخهٔ قدیمی‌تر را توصیف می‌کنند و ممکن است عقب بمانند.
