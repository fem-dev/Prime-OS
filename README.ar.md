# برايم-أو إس (Prime-OS)

[English](README.md) · [فارسی](README.fa.md) · **العربية** · [Español](README.es.md) · [Deutsch](README.de.md)

**Prime-OS** مشروع مجتمعي لبناء نظام تشغيل للألعاب مبني على **Arch Linux** ومدير النوافذ
[Hyprland](https://hyprland.org/) بواجهة Wayland. المرحلة الحالية هي **نسخة ISO حيّة تجريبية قابلة
للإقلاع** — وليست مُثبِّتًا مكتملًا ولا نظامًا جاهزًا للاستخدام اليومي.

> [!IMPORTANT]
> لا شيء في هذا المستودع يستبدل نظام تشغيلك. تطبيق الإعداد ينزّل صورة حيّة ويحفظ ملف تفضيلات فقط؛
> ولا يقوم بتقسيم الأقراص أو الكتابة على ذاكرة USB أو تثبيت النظام. اختبر الصورة أولًا داخل جهاز
> افتراضي، واستخدم ذاكرة USB فارغة عند الاختبار على جهاز حقيقي.

## البدء السريع

**لا تحتاج إلى Linux أو Docker أو أي خطوة بناء.** معالج الإعداد ينزّل ملف `os.iso` من أحدث إصدار
على GitHub، ويملأ رسم الفَرَوَهَري بنفس نسبة التنزيل الحقيقية: كل ١٪ تنزيل = ١٪ من الرسم.

### Windows

```powershell
irm https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.ps1 | iex
```

### Linux و macOS

```bash
curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.sh | bash
```

المتطلبات: **Python 3 مع Tk**، و**Git**، واتصال بالإنترنت، ومساحة حرة كافية للصورة. تُثبَّت حزمة
Pillow تلقائيًا داخل بيئة افتراضية خاصة.

ما الذي يفعله المعالج:

1. يفحص أحدث إصدار على GitHub بحثًا عن `os.iso`؛
2. ينزّله في مجلد التطبيق مع رسم تقدّم حيّ؛
3. يتحقق من الحجم، ومن SHA-256 المنشور إن وُجد ملف تحقّق؛
4. يحفظ ملف تفضيلات العتاد.

إذا لم يكن هناك إصدار منشور بعد، يقول ذلك بصراحة ويحفظ التفضيلات فقط — ولا يدّعي التثبيت أبدًا.

| | Windows | Linux / macOS |
| --- | --- | --- |
| ملفات التطبيق | `%LOCALAPPDATA%\Prime-OS` | `~/.local/share/prime-os` |
| التفضيلات | `%APPDATA%\Prime-OS\setup.json` | `~/.config/prime-os/setup.json` |

## تجربة الصورة الحيّة

اكتب `os.iso` على ذاكرة USB فارغة بأي أداة كتابة صور، أو أقلعها مباشرة في جهاز افتراضي UEFI.

```bash
# QEMU بقرص للقراءة فقط؛ لا يتغيّر شيء على النظام المضيف
qemu-system-x86_64 -m 4G -smp 2 -cpu max -enable-kvm \
  -drive file=os.iso,media=cdrom,readonly=on -boot d
```

على Windows يشغّل `./run-windows.sh` الملف `out/os.iso` داخل QEMU من Git Bash (يتطلب تثبيت QEMU).

## ما تحتويه النسخة التجريبية

- بيئة Arch Linux حيّة مبنية بملف التعريف الرسمي `archiso` (releng).
- Hyprland وWaybar وWofi وKitty وDunst وNetworkManager وPipeWire/WirePlumber.
- Steam وLutris وFirefox وتعريفات Mesa/Vulkan المعتادة.
- جلسة رسومية بسيطة عند أول إقلاع بمستخدم عادي غير مميّز باسم `prime`.
- معالج إعداد الفَرَوَهَري لأنظمة Windows وLinux وmacOS.

**غير مُنفَّذ بعد:** مُثبِّت على القرص، ودعم Secure Boot، ومسارات التحديث والاستعادة، والضبط التلقائي
للعتاد، وتهيئات مُختبرة لكل بطاقة رسوميات. لا يمكن لصورة ISO واحدة أن تضم كل التعريفات الاحتكارية؛
ودعم NVIDIA يعتمد على طراز البطاقة.

## الأمان وسلامة الملفات

- تُجلب وحدة الرسم `you.py` عبر HTTPS، وتُتحقَّق مقابل SHA-256 مثبَّت، ويتم **تحليلها** فقط دون تنفيذها.
- الشعار محدود الحجم وعدد البكسلات قبل فك الترميز، ويُتحقَّق من بصمته المثبَّتة.
- يجب أن يكون رابط تنزيل الإصدار HTTPS ويشير إلى مسار `releases/download` لهذا المستودع.
- التنزيل يذهب إلى ملف `.part` ولا يُنقل إلى مكانه إلا بعد تطابق الحجم — وبعد تطابق checksum إن كان منشورًا.
- تتحقق السكربتات من SHA-256 لكل ملف تُثبّته.
- البصمات مثبَّتة في `install.sh` و`install.ps1` و`loader.py` ويجب تحديثها معًا عند تغيير تلك الملفات.

تحقَّق بنفسك من الصورة:

```bash
sha256sum os.iso          # قارنها بملاحظات الإصدار أو ملف checksum
```

إذا لم تتطابق البصمة فلا تُقلع الصورة، وأبلغ عن المشكلة.

## بناء ISO (للمطوّرين فقط)

البناء اختياري ولا يلزم إلا لتعديل الصورة نفسها، ويتطلب Docker وعدة غيغابايتات من المساحة الحرة.

```bash
git clone https://github.com/fem-dev/Prime-OS.git
cd Prime-OS
docker run --rm --privileged \
  -e PRIME_OS_BUILD_CONTAINER=1 \
  -v "$PWD:/work" -w /work archlinux:latest \
  bash -lc 'pacman -Syu --noconfirm archiso && bash ./build.sh'
```

يرفض `build.sh` العمل خارج حاوية Arch مُعلَّمة صراحةً، وينسخ ملف تعريف releng الرسمي إلى
`.build/profile`، ويُفعّل مستودع `multilib` لـ Steam في ذلك الملف المؤقت فقط، ويدمج
`profile/packages.x86_64`، ويكتب الناتج في `out/os.iso`.

لا يستطيع Windows بناء ISO لـ Arch مباشرة — استخدم WSL2 مع توزيعة Arch أو `build.ps1` مع Docker Desktop.

### البناء في CI (GitHub Actions — دون بناء على جهازك)

1. افتح **Actions → Build and publish ISO → Run workflow**.
2. أدخل وسم الإصدار (افتراضيًا `os-preview`)؛ يُنشأ الإصدار إن لم يكن موجودًا.
3. تُبنى الصورة داخل حاوية Docker بصلاحيات privileged، ويعرض التقدّم **شريطًا واحدًا**، ثم يرفع
   `os.iso` و`os.iso.sha256` إلى ذلك الإصدار. ويُحفظ السجل الكامل كـ artifact.

دفع وسم `v*` يفعل الشيء نفسه. لا حاجة لبناء أي شيء على جهازك، ويمكن استخدام Codespace للاختبار
التفاعلي بالأمر نفسه مع أدوات Docker.

## هيكل المستودع

| المسار | الوظيفة |
| --- | --- |
| `loader.py` | معالج الإعداد: البحث عن الإصدار، تنزيل ISO، رسم التقدّم، ملف التفضيلات |
| `install.sh` / `install.ps1` | تثبيت بأمر واحد لـ Linux/macOS وWindows |
| `you.py` | مُصيّر الفَرَوَهَري المتّجهي (يُشحن كبيانات، يُحلَّل ولا يُنفَّذ) |
| `faravahar.png` | الشعار المستخدم في المعالج وفي الجلسة الحيّة |
| `profile/packages.x86_64` | حزم إضافية تُدمج في ملف archiso |
| `profile/airootfs/` | ملفات داخل الصورة الحيّة (Hyprland، Waybar، الدخول التلقائي، سكربت الإعداد) |
| `build.sh` / `build.ps1` | بناء ISO قابل للتكرار داخل Docker |
| `run-windows.sh` | إقلاع ISO المبني في QEMU من Git Bash |
| `requirements.txt` | اعتمادية بايثون (`Pillow`) |
| `.github/` | سير عمل Actions لبناء ISO ونشره في الإصدارات |

تبدأ الجلسة الحيّة مرة واحدة وعلى `tty1` عبر ملف الدخول التلقائي لـ `getty` مع
`/etc/skel/.bash_profile`؛ وينشئ `prime-os-live-setup` المستخدم غير المميّز `prime` ويثبّت ملف
الإعداد المرجعي `/etc/prime-os/hyprland.conf`.

## حالة المشروع

هذه نقطة بداية وليست ادعاءً بوجود نظام ألعاب مكتمل. الخطوات التالية: اختبار الصورة المنشورة على
عتاد حقيقي، وإصلاح مشاكل الإقلاع والحزم، وتصميم مُثبِّت، ثم إضافة تهيئات ألعاب مُختبرة ومسارات
تحديث واستعادة. تقارير اختبار العتاد والمساهمات مرحّب بها.

## المساهمة

- حافظ على صدق الصورة: لا ادعاء «بلا تقطيع» ولا أرقام أداء بلا قياس.
- اختبر في جهاز افتراضي أولًا، ولا تطلب من المستخدمين مسح ذاكرة تحتوي بياناتهم.
- إذا غيّرت `loader.py` أو `you.py` أو `faravahar.png` فحدّث البصمات المثبَّتة في نفس الالتزام؛
  فالمثبِّتات تفشل عن قصد عند عدم التطابق.
- أبلغ عن طراز بطاقة الرسوميات وإصدار التعريفات وما نجح وما فشل.
