**Prime-OS** — это сообщество-строительство системы операционных систем для игр на базе **Arch Linux** и Wayland-композитора **Hyprland**. Текущая миля스톤 — это **bootable live ISO** — не полный установщик и не готов к производству операционная система.

> [!IMPORTANT]
> Ни одна часть этого репозитория не заменяет вашу операционную систему. Приложение настраивает загрузку live-образа и сохраняет файл предпочтений; оно не разбивает диск, не записывает на USB-накопитель и не устанавливает Prime-OS. Сначала протестируйте образ в виртуальной машине, и используйте пустой USB-накопитель, если тестируете на реальном железе.

## Быстрый старт

**Вам не нужен Linux, Docker или любой шаг сборки.** мастер настройки загружает опубликованный `os.iso` из последнего релизе GitHub и заполняет искусство Faravahar с реальной прогрессом загрузки: один процент загружен — один процент рисунка.

### Windows

```powershell
irm https://raw.githubusercontent.com/fem-dev/Prime-OS/fd3cc79af467efa823645f73f2c3afad98529e10/install.ps1 | iex
```

> [!TIP]
> **Если команда для Windows завершается сетевой ошибкой** (`Unable to connect to the remote
> server`, `Could not connect to server` или тайм-аут), проблема в соединении с GitHub, а не в
> скрипте: **включите VPN и запустите ту же команду снова**. Если VPN уже включён и ошибка
> повторяется, **выключите VPN** (или смените сервер) и повторите — некоторые VPN, DNS-фильтры и
> корпоративные сети блокируют `raw.githubusercontent.com` и `github.com`. Затем откройте
> `https://github.com` в браузере, чтобы убедиться в соединении, и снова запустите команду.

### Linux и macOS

```bash
curl -fsSL https://raw.githubusercontent.com/fem-dev/Prime-OS/main/install.sh | bash
```

**Требования:** **Python 3 с Tk**, **Git**, интернет-соединение и достаточно свободного места для образа. Pillow автоматически устанавливается в приватное виртуальное окружение.

Мастер настройки выполняет следующие действия:

1. проверяет последнееrelease GitHub для `os.iso`;
2. загружает его в папку приложения с живой шкалой прогресса;
3. проверяет размер и опубликованную SHA-256, если релиз включает файл checksum;
4. сохраняет ваш профиль оборудования.

Если релис еще не опубликован, мастер просто говорит об этом и сохраняет только профиль — он не пытается pretend устанавливать операционную систему.

| | Windows | Linux / macOS |
| --- | --- | --- |
| Файлы приложения | `%LOCALAPPDATA%\\Prime-OS` | `~/.local/share/prime-os` |
| Настройки | `%APPDATA%\\Prime-OS\\setup.json` | `~/.config/prime-os/setup.json` |

## Попробовать live-образ

Запишите `os.iso` на пустой USB-накопитель с помощью любой утилиты записи образа или запустите его прямо в UEFI-виртуальной машине.

```bash
# QEMU, CD-ROM только для чтения, ничего на хосте не изменяется
qemu-system-x86_64 -m 4G -smp 2 -cpu max -enable-kvm \\
  -drive file=os.iso,media=cdrom,readonly=on -boot d
```

Под Windows `./run-windows.sh` запускает `out/os.iso` из Git Bash (QEMU requis).

## Что содержит эта экспериментальная версия

- Live Arch Linux окружение, построенное с официальным `archiso` releng профилем.
- Hyprland, Waybar, Wofi, Kitty, Dunst, NetworkManager и PipeWire/WirePlumber.
- Steam, Lutris, Firefox и usual Mesa/Vulkan.
- Минимальная графическая сессия как незарегистрированный пользователь `prime`.
- Faravahar wizard для Windows, Linux и macOS.

**Еще не реализовано:** дисковый установщик, поддержка Secure Boot, потоки обновления и восстановления, автоматическая настройка оборудования, и тестированные игровые профили. Одна ISO не может включить все проприетарные драйверы; поддержка NVIDIA зависит от модели видеокарты.

## Целостность и безопасность

- Модульное artistic `you.py` извлекается через HTTPS, проверяется против pinned SHA-256 и только **parsing**, никогда не выполняется мастером.
- Лого ограничено размером и пикселями перед декодированием, и проверяется против pinned SHA-256.
- URL-адреса загрузки релизов должны быть HTTPS и указывать на путь `releases/download` этого репозитория.
- Загрузки atterывают в файле `.part` и перемещаются на место только после размера — и опубликованной checksum, когда она доступна — соответствует.
- Скрипты проверяют SHA-256 каждого файла, который они устанавливают.
- Публикуемые хеши закреплены в `install.sh`, `install.ps1` и `loader.py`; они должны быть обновлены вместе каждый раз, когда эти файлы изменяются.

Проверьте скачанный образ сами:

```bash
sha256sum os.iso          # сравните с заметками к релизу или активом checksum
```

Декларируйте mismatch вместо того, чтобы загружать образ.

## Строить ISO (только для разработчиков)

Сборка является опциональной и нужна только если вы хотите изменить сам образ. Ее требует Docker и несколько гигабайт свободного места.

```bash
git clone https://github.com/fem-dev/Prime-OS.git
cd Prime-OS
docker run --rm --privileged \\
  -e PRIME_OS_BUILD_CONTAINER=1 \\
  -v \"$PWD:/work\" -w /work archlinux:latest \\
  bash -lc 'pacman -Syu --noconfirm archiso && bash ./build.sh'
```

`build.sh` отказывается работать вне явно отмеченного Arch-контейнера, копирует официальный releng профиль в `.build/profile`, активирует репозиторий `multilib` для Steam **только в этом временном профиле**, объединяет `profile/packages.x86_64`, и пишет результат в `out/os.iso`.

Windows не может построить ISO Arch directly — используйте WSL2 с distributions Arch, или `build.ps1` с Docker Desktop.

### Строить в CI (GitHub Actions, без локальной сборки)

1. Откройте **Actions → Build and publish ISO → Run workflow**.
2. Введите тег релиза (по умолчанию `os-preview`) — релис создается, если он не существует.
3. Работа выполняется в Docker-контейнере с привилегиями, отображает **одну шкалу прогресса**, после чего загружает `os.iso` и `os.iso.sha256` в этот релис. Полный журнал остается artifact'ом.

Публикация тега `v*` делает ту же самую вещь. Ничего не нужно строить на вашем собственном компьютере; Codespace работает для интерактивного теста с той же командой Docker, и обертка прогресса также работает там.

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `loader.py` | мастер настройки: поиск релиза, загрузка ISO, прогрессивное искусство, профиль |
| `install.sh` / `install.ps1` | Bootstrap в одну команду для Linux/macOS и Windows |
| `you.py` | Vector Art Faravahar (поставляется в данных, парсится, но не выполняется) |
| `faravahar.png` | Лого, используемый мастером и live-сессией |
| `profile/packages.x86_64` | Дополнительные пакеты, объединенные в профиль ArchISO |
| `profile/airootfs/` | Файлы в live-образе (Hyprland, Waybar, autologin, setup) |
| `build.sh` / `build.ps1` | Репродиуктивная сборка ISO в Docker |
| `run-windows.sh` | Запуск ISO в QEMU из Git Bash |
| `web_search.py` | Поисковый помощник Exa для contributeurs и agents (`EXA_API_KEY`) |
| `.env.example` | Заглушка переменных окружения; скопируйте в `.env` (git-ignored) |
| `requirements.txt` | Python зависимости (`Pillow`, `exa-py`) для мастера настройки и помощника поиска |
| `NOTICE.md` | Что проект есть и нет: лицензия, торги, безопасность, статус |
| `.github/` | Workflow, который строит ISO и публикует его в релизы |

Live-сессия запускается один раз на `tty1` через drop-in `getty` autologin плюс `/etc/skel/.bash_profile` ; `prime-os-live-setup` создает непривилегированного пользователя `prime` и устанавливает canonical `/etc/prime-os/hyprland.conf`.
